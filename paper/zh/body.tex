\section{引言}
稀疏注意力门控电路的工程价值，既取决于评分与选择的数据通路，也取决于完整的数据传输和控制链路。输入记录必须实际送达硬件，算术运算必须满足明确的选择规则，选中的数据必须完成读取，而命令完成状态则必须沿处理器的实际访存路径返回。仅通过离线回放拼接时序，无法验证上述依赖关系。

2026 年 9 月随 DeepSeek-V4.1-Flash 发布的 CSA2，提供了公开的模型配置、低精度数据格式和参考代码，因而适合作为本研究的近期算法对象~\cite{csa2,csa2code}。CSA2 在 DSA 所采用的可学习加权 ReLU 索引方法基础上，进一步引入压缩表示，以及跨层 KV 与索引复用~\cite{dsa}。这些算法机制来自所引文献。本文的贡献在于明确范围内的数字电路实现及其系统集成验证。

本文以研究仓库中记录的固定版本 StorageStacked 为基础~\cite{upstream}，保留其三个处理源及在线访存返回路径。CPU 使用 gem5 时序 CPU 模型执行程序，Vortex 使用 SimX 模型，CoralNPU 使用基于 RTL 的模型。该系统运行于系统调用仿真模式（syscall emulation，SE），CPU 程序与栈所在的存储器不属于远端目标存储区域。因此，本文系统既不等同于全芯片 RTL 模型，也不具备三个设备之间的缓存一致性。

本文完成三方面工程工作。首先，以完整的 FP4 评分与选择数据通路替代固定规模的池化块门控，支持 32 个索引头、128 维向量及最大 512 的 K 值。其次，在存储侧实现寄存器与直接存储器访问（direct memory access，DMA）端点，使普通访存、候选索引读取、结果写回和选中 KV 搬运共用既有存储后端及统一时间轴。最后，通过固定版本的官方源码与权重子集、独立数值参考模型、背压与错误检查，以及范围明确的综合证据，将算法的数值约定落实到实际 RTL。上述工作不构成新的稀疏注意力算法，也不支持尚未测量的完整模型加速结论。

\section{从池化门控到可学习索引}
\subsection{原论文的架构基础}
王瑞泰的学位论文~\cite{wang}提出了较为完整的池化门控架构：由 128 个 Block 构成，每个 Block 包含 32 个 Cell，每个 Cell 存储 32 个 BF16 数值，并配有均值池化、空间并行归约和 32 个独立的 Top-K 模块。其给出的映射以 32 个词元块为输入，选出其中 12 个块。面向分组查询注意力（grouped-query attention，GQA）的四份复制，使 64 KiB 的独立摘要数据对应的 Kmean 载荷达到 256 KiB。这些容量由论文中的结构参数推算得到，并非本文设计的实测结果。

原论文的逐位竞争网络是在一个时钟周期内传播的组合逻辑链，每周期选出一个胜者，而非每个分数位消耗一个时钟周期。本文并未将这一网络直接扩展到长序列和 Top-512。原论文在数字综合中将 SRAM 存内计算（SRAM-CIM）单元作为黑盒，其宏单元估计取自引用文献；文中给出的 7 nm 结果还包含由 28 nm 结果进行工艺归一化的步骤。本文不沿用这些数值，也不声称实现了新的物理 SRAM-CIM 宏。由于未获得原作者交付的 RTL 与宏单元特性数据，本文依据论文公开的设计思想独立重构架构。

\subsection{目标算子与实现范围}
对于单个查询，投影后的索引分数为
\begin{equation}
 s_i=\sum_{h=0}^{H-1}w_h\operatorname{ReLU}\!\left(\sum_{d=0}^{127}q_{h,d}k_{i,d}\right),\quad H\le32.
\label{eq:score}
\end{equation}
其中，所有索引头共享同一个索引键向量 $k_i$。输入的 BF16 权重 $w_h$ 已包含官方投影头权重及其 $D^{-1/2}H^{-1/2}$ 缩放因子，RTL 不再重复执行该归一化。学习得到的 $w_h$ 可以为负，因此必须先完成每个头的点积，再应用 ReLU，随后进行有符号加权。将 ReLU 移至跨头求和之后会改变算法语义。本文不以各头贡献均非负这一错误假设进行提前剪枝。

官方 CSA2 配置采用 32 个索引头、128 维向量和 Top-512。本文的 $N$ 表示压缩后的索引/KV 记录数，$i$ 表示这些记录的原始位置，而非原始词元编号。当压缩索引与滑动窗口条目合并时，软件负责应用官方定义的偏移，并处理不可见条目对应的 $-1$ 占位符。官方候选来源层构建每块含 8 个位置、最多 2048 个块的候选块池，并保留最新的不足一个整块的尾块。本文硬件接收展开后的有效候选索引列表，要求索引按升序排列且不重复。候选块池生成、压缩、Q/K 投影、均方根归一化（RMSNorm）、旋转位置编码（RoPE）、量化及稀疏注意力运算均由处理器或软件完成。在预填充阶段，软件先将块掩码与可见位置求交，再发起物理读取。下文所述硬件模式对应上述算子边界内的执行方式，并不表示已实现 CSA2 中全部层角色。

\section{数值约定与微架构设计}
\subsection{紧凑记录格式与组内精确运算}
索引器采用 E2M1 FP4 数值，每 32 维共享一个 E8M0 缩放因子~\cite{csa2code,mx}。FP4 并非有符号均匀 INT4 格式。将 E2M1 数值乘以 2 后，可得整数集合
\begin{equation}
 \mathcal M=\{0,\pm1,\pm2,\pm3,\pm4,\pm6,\pm8,\pm12\}.
\end{equation}
组内点积 $D_{h,g}=\sum_{j=0}^{31}m^q_{h,g,j}m^k_{i,g,j}$ 可在 $[-4608,4608]$ 范围内精确计算。对于缩放字节 $e_q,e_k$，该组的 FP32 贡献为
\begin{equation}
 a_{h,g}=\operatorname{RNE}_{32}\!\left(D_{h,g}\,2^{e_q+e_k-256}\right).
\end{equation}
其中，$\operatorname{RNE}_{32}$ 表示采用“舍入到最近值、中点取偶”的 FP32 舍入规则。实现中依次累加四个组的贡献，应用 ReLU，再与精确扩展为 FP32 的有限有符号 BF16 权重相乘，最后按顺序累加各头结果。每次浮点运算均采用上述舍入规则，并支持渐进下溢，即保留可表示的次正规数。对于实际读取的记录，若 E8M0 字节为 255、权重为非有限值，或中间 FP32 结果溢出，硬件将报错且不输出成功的选择结果。仅扫描候选位置时，未读取的键记录不进行格式检查。

明确的数值约定使 RTL 与独立参考模型能够进行逐位比对，但并不保证与采用其他累加顺序或 BF16 输出舍入的 GPU 内核逐位等价。分数相同时优先保留索引较小的条目，正零与负零也按相等分数处理。

\subsection{共享键缓冲与有界选择结构}
查询（Q）缓冲存储 32 条记录，每条包含 64 B 紧凑数值、4 B 缩放因子和 2 B 权重，逻辑载荷共 2240 B。一个 68 B 的键（K）缓冲在所有索引头之间复用。物理存储中，每条 Q 或 K 记录占 96 B，即三个对齐的 AXI256 数据拍；填充字节也计入传输量。每个参与评分的键记录只读取一次，无需为每个索引头分别建立存储副本。

最小堆最多存储 512 对 32 位分数与 32 位索引，逻辑载荷为 4 KiB。按上述稳定排序规则，堆根始终为当前保留候选中最差的条目。新分数到达后，执行追加、替换堆根或丢弃操作；堆调整需要 $O(\log K)$ 次比较，每一步至多考察两个子节点。核心通过带有 valid/ready 握手和有限缓冲的接口传递分数与结果。封装模块将堆输出收集到独立的 4 KiB 结果缓存，并通过插入排序按索引升序输出。这一位置排序在最坏情况下的复杂度为 $O(K^2)$，是明确的面积与延迟折中，并非常数时间排序。

\section{在线系统集成与命令完成规则}
\subsection{RTL 边界与协议适配}
原存储目标通过 C++ FIFO 对象传递完整突发请求，并不直接提供 RTL AXI 引脚。新增分发器将寄存器请求转换为实际的 AXI 从通道握手，并将 RTL DMA 事务转换为对同一个 MemSimBackend 的请求。分发器不计算分数、不维护私有数据镜像，也不预测存储访问何时完成。原生 mem\_sim 接收请求后，在后续返回数据字节与完成事件，再由这些事件驱动 RTL 响应通道。

RTL 顶层采用 64 位地址、16 位事务标识、256 位数据和 32 位写字节选通信号 WSTRB。验收配置的存储地址窗口为 1 MiB，其中预留 4 KiB 的存储器映射输入输出（memory-mapped I/O，MMIO）窗口；各数据缓冲区必须完整落在配置的地址范围内。分发器拒绝独占访问请求。写地址（AW）与写数据（W）通道分别缓冲，响应载荷在背压期间保持稳定。从接口支持自然对齐、宽度不超过 32 B 的单数据拍访问；不支持的突发请求返回错误，并完成必要的排空处理。DMA 每次仅发出一个对齐的 32 B INCR 数据拍。内部响应标签与处理器侧原有事务标识分离，因此即使 DMA 使用 ID 1，也不会产生标识混淆。

所有 Verilator 求值均发生在既有 SystemC 时钟边沿，与 gem5 共用飞秒级时间轴，且不链接第二套 SystemC 内核。普通流量保留独立队列，与 DMA 共同访问在线存储后端。当前实现最多保留一个未完成的 DMA 请求，这是明确的吞吐率限制。

\subsection{执行模式与结果提交}
FULL 模式扫描调用方给定的有效键区间。REINDEX 模式仅读取指定候选位置，并检查索引是否唯一、升序且未越界。REUSE 模式要求已经存在成功提交的选择结果，且上下文标识、版本号（epoch）、键数量、头数量、K 值、Q 地址和 K 地址均匹配。该模式不读取 Q/K，也不重新评分，但仍执行结果写回和所请求的 KV 聚集读取与搬运。源数据发生变化时，软件必须递增版本号或使缓存失效。这一显式协议不提供硬件缓存一致性，也不是访问控制机制。

每个结果占一条 32 B 记录，包含索引、FP32 分数位模式及零填充。选中的紧凑主 KV 记录按索引顺序读取并复制到聚集输出区。只有所有输出写响应（BRESP）均成功后，硬件才提交 DONE 完成状态。失败命令可能已产生部分写入，但错误状态禁止调用方将这些数据作为完整结果使用。后续新命令可以从错误状态恢复；命令在途期间的外部复位恢复不在当前接口约定范围内。

\subsection{传输量统计}
设有效候选数量为 $1\le C\le N$；REINDEX 不接受空列表。FULL 的结果数量为 $R=\min(K,N)$，REINDEX 为 $R=\min(K,C)$，REUSE 则沿用此前成功提交的结果数量。因此，在候选数量不足 K 的选择之后执行复用，仍保留此前较小的结果数量。若 KV 记录大小 $V$ 为 32 B 的整数倍，物理 DMA 数据拍数量为
\begin{align}
 B^\mathrm{full}_\mathrm{read}&=3H+3N+RV/32,\\
 B^\mathrm{reindex}_\mathrm{read}&=3H+3C+\lceil C/8\rceil+RV/32,\\
 B^\mathrm{reuse}_\mathrm{read}&=RV/32,\\
 B_\mathrm{write}&=R(1+V/32).
\end{align}
上述计数不包含处理器侧的初始上传、MMIO、结果回读和 UCIe 成帧开销，这些流量在系统轨迹中另有记录。复用与分层候选均为 CSA2 已有机制，其传输量减少不构成本文新的算法发现。完整的架构比较还应纳入计算侧常驻索引缓存，而不能假设所有对比方案每次均需跨 UCIe 重新加载全部键。

\section{验证方法与实验结果}
\subsection{独立参考模型与预训练权重}
官方源码和第 20 层的五个索引器张量均固定到指定版本。通过 HTTP 范围请求，仅获取 \TensorBytes{} 字节张量数据，无需下载完整检查点。这些张量提供学习得到的 Q/K 投影、归一化参数与头权重。中间激活采用独立随机种子生成的高斯数据，并明确标记为合成输入；它们并非由文本驱动的完整模型推理中提取的隐藏状态。

独立参考模型将有限中间数表示为整数与 2 的整数次幂的乘积，并独立实现 IEEE FP32 舍入。对于加法和乘法，分别使用 \OraclePairCount{} 对有限输入与 NumPy 交叉核对；此外，还执行 \RationalCaseCount{} 个基于精确有理数的舍入区间检查。RTL 浮点运算模块通过 \FpCaseCount{} 个用例验证，覆盖溢出与次正规数。通过验收的核心测试集包含 \CoreCaseCount{} 个用例、\CoreKeyCount{} 个成功键评分，以及实际执行的 \CoreMacCount{} 个 FP4 乘积项。错误用例必须返回预期错误，且不产生选中结果。测试覆盖完整 H32/N640/K512 的预训练权重派生输入，以及仅扫描候选位置的输入。

\section{讨论与局限}
现有证据验证了可复现的算子算术与在线存储时序反馈，尚不能确定完整模型的吞吐率、质量、能耗或量产芯片工作频率。已完成的多处理源共存测试，也不能证明 GPU/NPU 在门控执行期间发生并发争用。

当前字节加载接口和最多仅允许一个未完成请求的 DMA 使部分工作串行执行。按位置排序采用了较简单的实现，映射为触发器的状态存储也带来显著面积开销。后续可针对这些限制开展具体改进，包括加宽 Q/K 加载接口、采用双缓冲、重叠评分与堆操作、支持数量受限的多个未完成 DMA 请求，以及绑定经过特性表征的 SRAM 宏。各项改进均应在相同数值约定与资源约束下评估。完整扫描的索引评分仍需执行 $NHD$ 个标量乘积，最终注意力的稀疏性并不消除这部分开销。
